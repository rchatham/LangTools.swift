How LangTools.swift compares

Request encoding and response decoding against three Swift clients. These tests measure local JSON serialization—not API latency, streaming throughput, model quality, or overall application speed.

Measured September 14, 2026 · Swift 6.1.0 · arm64 macOS 15.6 · after the OpenAI request encoder optimization · dedicated results-file capture

Working-tree results: the latest encoder change is uncommitted and its independent review is pending. This is not a benchmark of a published LangTools.swift release.

What the results support

Simple requests: lowest observed encode time

LangTools took less encoding time than SwiftOpenAI, MacPaw/OpenAI, and SwiftAnthropic on their respective matching request fixtures in both release runs.

Large requests: lowest observed encode time

LangTools had the lowest normalized encoding time among the tested clients for 50-message requests. The request JSON matched before timing.

Decode speed needs context

LangTools approximately tied MacPaw and took less time than SwiftOpenAI and SwiftAnthropic. SDK models and required decoder settings still differ; these are fixture-specific results.

How the measurements work

  1. Match the workload. OpenAI requests use gpt-4o and stream: false. Anthropic requests use claude-sonnet-4-6, max_tokens: 4096, and stream: false. Message contents, roles, and emitted fields match within each encode pair.
  2. Warm up and alternate. Each comparison runs two warmup batches per variant, then ten measured pairs alternating AB/BA order in the same process. The entire suite is repeated in a second release run.
  3. Time batches, not network requests. Simple encode uses 10,000 operations per batch; large encode 1,000; decode 5,000. Encoders/decoders and inputs are prepared outside timing. No live API calls are made.
  4. Normalize within each pair. The artifact records the median of ten LangTools/competitor time ratios. The main tables invert that median so each alternative reads as time relative to LangTools = 1.000×. This is not a ratio of independently averaged timings.

Environment: local arm64 macOS 15.6 (24G84), Swift 6.1.0, release SwiftPM builds. There are only two runs on one environment; differences near parity can change with hardware, compiler, load, model shape, or library version. Decode outputs are held through withExtendedLifetime; this does not benchmark downstream application use.

What these tests do not establish
  • No end-to-end API latency, network throughput, time to first token, concurrency scaling, memory usage, or allocation counts were measured here.
  • No cross-device or cross-platform performance guarantee. Production builds with different settings can differ from these release test builds.
  • Text-message request fixtures do not represent every multimodal, tool-heavy, or structured-output workload. Rich-field correctness tests are not a full competitor performance matrix.
  • No current normalized stream-chunk, message-construction, or round-trip comparison is included. Older tests of those operations are not silently mixed into this table.
  • The winner labels are descriptive, not significance tests; decode models and required transformations still differ.

Reproduce & inspect the evidence

Enable the three commented competitor package dependencies and BenchmarkTests product dependencies in Package.swift, including the MacPawOpenAI module alias. Then run twice:

LANGTOOLS_RUN_PAIRED_BENCHMARKS=1 Scripts/run-extended-tests.sh \
  -c release --filter PairedCompetitorBenchmarkTests

Match the versions/revisions above rather than assuming current branch or semver resolution matches this snapshot. Restore dependency comments and lockfiles afterward; competitor packages remain opt-in. The exact LangTools state includes uncommitted changes, so reproducing a published release will not reproduce this snapshot.

  • Current raw results and dependency revisions — use the final two runs for these competitor comparisons; earlier runs in that file are separate encoder experiments.
  • Request encoder investigation — implementation decision, correctness checks, before/after results, and review status.
  • Paired benchmark source and additional competitor fixtures.

Raw artifacts retain measurements for a retired comparison client that is no longer in the active suite or tables. The current page shows only the three alternatives listed above; retained measurements have not been edited or re-run.
